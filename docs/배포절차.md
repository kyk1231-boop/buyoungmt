## 1. Supabase — 데이터베이스 (15분)

### 1-1. 프로젝트 만들기

1. https://supabase.com 접속 → **Start your project** → 구글 계정으로 로그인
2. **New project** 클릭
3. 입력값
   - Name: `buyoungmt`
   - Database Password: 아무거나 길게. **이건 관리자 비밀번호와 다른 것이다.** 메모해두되 앞으로 쓸 일은 거의 없다
   - **Region: `Northeast Asia (Seoul)`** ← 가장 중요하다
4. **Create new project** → 2분쯤 기다린다

> **리전을 왜 반드시 서울로 하는가**
> 고객 담당자의 성함과 연락처가 저장된다. 서울을 고르면 국내에 저장되어 개인정보 국외이전 고지 의무가 생기지 않는다. 다른 곳을 고르면 개인정보처리방침을 다시 고쳐야 하고, 나중에 바꾸려면 데이터를 통째로 옮겨야 한다.

### 1-2. 표 만들기

1. 왼쪽 메뉴 **SQL Editor** → **New query**
2. 이 폴더의 `db/schema.sql` 파일을 메모장으로 열어 **전체 복사**
3. 편집창에 붙여넣고 **Run** (또는 Ctrl+Enter)
4. `Success. No rows returned` 가 나오면 성공

### 1-3. 값 두 개 복사

왼쪽 메뉴 **Project Settings** → **API**

| 화면의 이름 | 나중에 쓸 이름 |
|---|---|
| Project URL | `SUPABASE_URL` |
| service_role (Reveal 눌러야 보임) | `SUPABASE_SERVICE_ROLE_KEY` |

메모장에 붙여두고 4단계에서 쓴다.

> **`service_role` 키는 데이터베이스 전체 권한이다.** 이게 새면 고객 명단 전체가 열린다. 카톡·메일·문자로 보내지 말고, 4단계에서 Vercel 화면에 직접 붙여넣는다. 나에게도 알려줄 필요 없다.

## 3. 관리자 비밀번호 등록 (5분)

이 시스템은 비밀번호를 그대로 저장하지 않는다. 되돌릴 수 없는 형태로 바꿔서 저장한다.

1. 이 폴더에서 터미널을 열고 실행 (`0000` 자리에 실제 정한 비밀번호)

```
node scripts/hash-password.js "0000"
```

2. `scrypt$...` 로 시작하는 긴 문자열이 나온다. 복사한다
3. Supabase → **SQL Editor** → 아래를 붙여넣되 `여기에붙여넣기` 를 복사한 값으로 바꾼다

```sql
insert into admin_settings (id, password_hash)
values (1, '여기에붙여넣기')
on conflict (id) do update set password_hash = excluded.password_hash;
```

4. **Run**

> 이 단계를 건너뛰고 로그인하면 5회 실패로 15분 잠긴다. 반드시 배포 전에 해둔다.

## 4. Vercel — 인터넷에 올리기 (15분)

### 4-1. 배포

1. 이 폴더에서 터미널을 열고 실행

```
npx vercel
```

2. 물어보는 것에 답한다
   - `Set up and deploy?` → **y**
   - `Which scope?` → 본인 계정 선택
   - `Link to existing project?` → **n**
   - `What's your project's name?` → `buyoungmt`
   - `In which directory is your code located?` → 그냥 Enter (`./`)
   - 나머지 설정 → 전부 Enter (기본값)
3. 처음이면 브라우저가 열려 로그인하라고 한다. 구글 계정으로 로그인
4. 끝나면 `https://buyoungmt-xxxx.vercel.app` 같은 주소가 나온다. **이 주소를 메모한다**

### 4-2. 환경변수 넣기

1. https://vercel.com → 프로젝트 `buyoungmt` → **Settings** → **Environment Variables**
2. 아래 7개를 하나씩 추가한다. 셋 다(Production·Preview·Development) 체크한 채로 저장한다

| 이름 | 값 |
|---|---|
| `SUPABASE_URL` | 1-3에서 복사한 Project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | 1-3에서 복사한 service_role 키 |
| `SESSION_SECRET` | 아래 4-3 참고 |
| `RESEND_API_KEY` | 2단계에서 복사한 키 |
| `MAIL_FROM` | `부영미트 견적문의 <onboarding@resend.dev>` |
| `NOTIFY_EMAILS` | `siaabba@naver.com,kyk12318638@naver.com` |
| `SITE_URL` | 4-1에서 나온 `https://...vercel.app` 주소 |

### 4-3. SESSION_SECRET 만들기

로그인 상태를 위조하지 못하게 막는 열쇠다. 터미널에서 실행해 나온 값을 쓴다.

```
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### 4-4. 다시 배포

환경변수는 다음 배포부터 적용된다. 터미널에서 실행한다.

```
npx vercel --prod
```

## 5. 확인 (10분)

배포된 주소로 접속해 아래를 순서대로 해본다. **하나라도 안 되면 다음으로 넘어가지 말고 알려달라.**

1. `/inquiry.html` 에서 견적 문의를 실제로 한 건 넣는다 → **"견적 요청이 접수되었습니다"** 가 뜨는가
2. 두 이메일(`siaabba@naver.com`, `kyk12318638@naver.com`)에 알림이 왔는가 — 스팸함도 확인
3. `/admin` 접속 → 비밀번호 입력 → 로그인되는가
4. 방금 넣은 문의가 목록에 보이는가
5. 상태를 `연락함` 으로 바꾸고 새로고침해도 유지되는가
6. 처리자를 지정하고 유지되는가
7. 연락처를 눌렀을 때 전화가 걸리는가 (휴대폰에서)
8. **비밀번호를 8자 이상으로 바꾼다** ← 가동 후 제일 먼저 할 일

> **8번을 미루지 않는다.** 초기 네 자리 비밀번호는 조합이 1만 가지뿐이다. 잠금은 접속 주소 단위라 주소를 바꿔가며 시도하면 우회된다.

## 6. 도메인 연결 (나중에)

임시 주소로 며칠 써보고 문제가 없으면 `buyoungmt.com` 을 붙인다.

1. Vercel → 프로젝트 → **Settings** → **Domains** → `buyoungmt.com` 추가
2. Vercel이 알려주는 값을 아이네임즈 DNS 관리에 넣는다
3. 연결되면 `SITE_URL` 환경변수를 `https://buyoungmt.com` 으로 바꾸고 다시 배포한다
4. 이때 함께 할 일 — 검색 노출용 정리(canonical 주소, 카카오톡 공유 미리보기 이미지, sitemap.xml)와 네이버 스마트플레이스에 홈페이지 주소 등록

## 문제가 생기면

| 증상 | 원인 |
|---|---|
| 문의 넣으면 "전송에 실패했습니다" | `SUPABASE_URL` 또는 `SUPABASE_SERVICE_ROLE_KEY` 가 틀렸거나, 1-2 표 만들기를 안 했다 |
| 접수는 되는데 메일이 안 옴 | `RESEND_API_KEY` 또는 `MAIL_FROM` 확인. 스팸함도 본다 |
| `/admin` 에서 "비밀번호가 맞지 않습니다" | 3단계 비밀번호 등록을 안 했을 수 있다 |
| `/admin` 에서 "서버에 문제가 있습니다" | 환경변수가 빠졌다. 7개가 다 있는지 본다 |
| 15분 잠김 | 5회 틀렸다. 기다리거나 Supabase SQL Editor 에서 `delete from login_attempts;` 실행 |
